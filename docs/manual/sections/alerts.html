告警设置

告警功能支持三种通知渠道：Webhook、QQ 通知、SMTP 邮箱。当 Bot 掉线或容器异常时自动推送通知。

通知渠道

渠道触发方式适用场景
QQ 通知通过在线的哨兵 Bot 发送私聊/群聊消息最即时，适合个人或小群运维
SMTP 邮箱发送邮件到指定收件人，附带扫码链接适合需要邮件归档的团队
WebhookPOST JSON 到指定 URL对接企业微信/钉钉/飞书/AstrBot 等

QQ 通知

选择一个或多个在线 Bot 作为哨兵（sender_bots），指定通知目标（私聊 QQ 号或群号）。当任意被监控的 Bot 掉线时，系统从哨兵列表中选取第一个在线的 Bot 发送告警消息。

哨兵 Bot 的在线状态由管理器与互联插件的 WS 连接决定（bot_online 字段），不依赖 OB11 WS 连接状态。

SMTP 邮箱通知

  1. 在告警设置页面配置统一的 SMTP 发件服务（Host/端口/用户名/密码/SSL）
  2. 点击「添加 SMTP 邮箱通知」，选择要监听的容器，填入收件邮箱
  3. 可选填「面板公网地址」，掉线邮件中会包含扫码链接
每条 SMTP 规则可独立指定收件邮箱，支持逗号分隔多个地址。规则创建后可点击「测试」验证邮件发送。

Webhook 告警

创建规则时指定告警类型和 Webhook URL，触发时 POST JSON payload。

告警类型

类型说明
instance_offline实例停止/离线
login_lost账号掉线/需扫码
instance_online实例上线
container_stop容器停止
high_cpuCPU 超限
high_mem内存超限
login_failure登录失败

允许所有 IP 访问

默认启用 SSRF 防护，Webhook URL 不可指向内网地址。如果通知插件与管理器同机部署，开启此开关允许 localhost/内网 IP。

Webhook 格式兼容 AstrBot Webhook Push 插件：http://<IP>:60071/common-webhook
